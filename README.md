# منصة أنسام الإدارية

منصة إدارية متكاملة لشركة **أنسام** — خدمات الصيانة والتبريد والتكييف وصيانة المطابخ والأفران الكبيرة.
مبنية بالكامل على **Cloudflare** (Pages + Functions + D1) مع نسخ احتياطي اختياري إلى **Google Sheets**.

---

## ✨ المزايا

| القسم | الوصف |
|------|-------|
| **لوحة المعلومات** | الأرقام الأساسية (الإيرادات، المصروفات، صافي الدخل، عدد الفواتير/العروض/الموظفين)، رسوم بيانية شهرية، وتوزيع طرق الدفع. |
| **المالية** | تسجيل الإيرادات والمصروفات بثلاث طرق دفع: **نقدي / حوالة / جهاز شبكة**. الدفع النقدي يربط تلقائياً بالموظف المستلم (عهدة النقد)، مع ملخص لكل موظف. |
| **الفوترة** | إصدار فواتير مباشرة برقم تلقائي وتاريخ اليوم — **الهيدر الثابت** (بيانات الشركة) يُدخل مرة واحدة، وأنت فقط تغيّر بيانات العميل والبنود. طباعة / حفظ PDF بتصميم أنيق. |
| **عروض الأسعار** | نفس آلية الفوترة، مع إمكانية **تحويل العرض إلى فاتورة** بضغطة زر. |
| **الموظفون** | إضافة موظف بالاسم + اسم دخول + كلمة مرور + **رمز موظف**، مع صلاحيات (مدير/موظف)، تعديل وحذف — كل ذلك من لوحة الإدارة. |
| **الموقع الرسمي** | صفحة هبوط مستقلة وأنيقة للعملاء، **محتواها قابل للتحكم بالكامل** من صفحة الإعدادات. |
| **النسخ الاحتياطي** | كل البيانات محفوظة في قاعدة Cloudflare D1، مع نسخة احتياطية اختيارية تلقائية إلى Google Sheets. |

- 🎨 الهوية البصرية لأنسام (الألوان + الشعار) وخط **Clother Arabic**.
- 🌐 واجهة عربية بالكامل (RTL) بتصميم فخم وسلس.
- 🔐 نظام دخول آمن (تشفير كلمات المرور PBKDF2 + جلسات).

## 🚀 التشغيل محلياً

```bash
npm install --legacy-peer-deps      # تثبيت الحزم
npm run build                       # بناء الواجهة

# تجهيز قاعدة البيانات المحلية
npx wrangler d1 execute ansam-db --local --file=./schema.sql
npx wrangler d1 execute ansam-db --local --file=./seed.sql

# تشغيل المنصة كاملة (واجهة + API)
npx wrangler pages dev dist --port 8788
# افتح: http://localhost:8788
```

> للتطوير على الواجهة مع إعادة التحميل الفوري: شغّل `npm run dev` في نافذة، و`wrangler pages dev` في أخرى.

### 🔑 بيانات الدخول الافتراضية
```
اسم الدخول : admin
كلمة المرور : Ansam@2026
```
**غيّر كلمة المرور فوراً** بعد أول دخول من: الإعدادات ← الأمان.

## ☁️ النشر على Cloudflare

1. **أنشئ قاعدة D1:**
   ```bash
   npx wrangler d1 create ansam-db
   ```
   انسخ `database_id` الظاهر والصقه في `wrangler.toml`.

2. **جهّز الجداول والبيانات الأولية على السحابة:**
   ```bash
   npx wrangler d1 execute ansam-db --remote --file=./schema.sql
   npx wrangler d1 execute ansam-db --remote --file=./seed.sql
   ```

3. **عيّن سراً قوياً للجلسات** (من لوحة Cloudflare > المشروع > Settings > Variables، أو):
   ```bash
   npx wrangler pages secret put SESSION_SECRET
   ```

4. **انشر:**
   ```bash
   npm run build
   npx wrangler pages deploy dist
   ```

> يمكن أيضاً ربط المستودع مباشرة بـ Cloudflare Pages مع أمر البناء `npm run build` ومجلد الإخراج `dist`، مع إضافة ربط D1 باسم `DB`.

## 🌐 فصل الموقعين عبر النطاقات

الموقعان يُنشران معاً من **نشر واحد** على Cloudflare، لكنهما مفصولان عبر نطاقين مختلفين، ويوجّه التطبيق نفسه تلقائياً حسب النطاق (انظر [`src/lib/sites.ts`](./src/lib/sites.ts)):

| الموقع | النطاق |
|--------|--------|
| **الموقع الرسمي** (صفحة الهبوط) | `ansamair.sa` (و`www.ansamair.sa`) |
| **المنصة الإدارية** (الدخول/اللوحة/البوابة) | `app.ansamair.sa` |

كيف يعمل التوجيه:
- على `ansamair.sa` تُعرض **صفحة الهبوط فقط**؛ وأي طلب لمسار إداري (`/login`، `/app`، `/portal`) يُحوَّل تلقائياً إلى `app.ansamair.sa`.
- على `app.ansamair.sa` تُعرض **المنصة الإدارية فقط**؛ والجذر `/` يوجّه إلى `/app`.
- صفحة الهبوط تجلب محتواها القابل للتحكم عبر `‎/api/public/landing`‎، وبما أن الـ API يُخدَم من نفس النشر فهو متاح على النطاقين دون أي إعداد CORS.
- محلياً / على معاينات `*.workers.dev` يبقى الموقعان متاحين معاً على نفس المضيف لتسهيل التطوير.

لتغيير النطاقين دون تعديل الكود، عيّن متغيّرَي البيئة وقت البناء:
```bash
VITE_PUBLIC_DOMAIN=ansamair.sa
VITE_ADMIN_DOMAIN=app.ansamair.sa
```
وحدّث القائمة `routes` في [`wrangler.toml`](./wrangler.toml) بنفس النطاقات.

## 🔁 النقل إلى حساب Cloudflare جديد

1. **سجّل الدخول للحساب الجديد:**
   ```bash
   npx wrangler logout && npx wrangler login
   ```
2. **أضف النطاق `ansamair.sa` كـ Zone** في لوحة Cloudflare للحساب الجديد ووجّه سجلات NS إليه (من مزوّد النطاق).
3. **أنشئ قاعدة D1 جديدة على الحساب الجديد** وحدّث `database_id` في `wrangler.toml`:
   ```bash
   npx wrangler d1 create ansam-db
   npx wrangler d1 execute ansam-db --remote --file=./schema.sql
   npx wrangler d1 execute ansam-db --remote --file=./seed.sql
   ```
   > لنقل البيانات القائمة من الحساب القديم: صدّرها من هناك بـ
   > `npx wrangler d1 export ansam-db --remote --output=backup.sql`
   > ثم نفّذها على الجديد بـ `--file=./backup.sql`.
4. **عيّن سرّ الجلسات على الحساب الجديد:**
   ```bash
   npx wrangler secret put SESSION_SECRET
   ```
5. **انشر** — ستُنشأ النطاقات المخصّصة الثلاثة تلقائياً من `routes`:
   ```bash
   npm run build && npx wrangler deploy
   ```
6. تحقّق أن `ansamair.sa` تفتح صفحة الهبوط وأن `app.ansamair.sa` تفتح المنصة.

## 📊 النسخ الاحتياطي إلى Google Sheets (اختياري)

1. افتح ملف [`google-apps-script.js`](./google-apps-script.js) واتبع الخطوات المكتوبة في أعلاه.
2. انسخ رابط الـ Web App والصقه في: **الإعدادات ← النسخ الاحتياطي**، وفعّل الخيار.
3. ستُرسل كل فاتورة / عرض / حركة مالية جديدة تلقائياً إلى الجدول.

## 🗂️ بنية المشروع

```
├── functions/api/[[path]].ts   # واجهة الـ API (Cloudflare Functions + D1)
├── src/
│   ├── pages/                  # الصفحات (لوحة، مالية، فوترة، عروض، موظفون، إعدادات، هبوط، دخول)
│   ├── components/             # مكونات الواجهة المشتركة
│   └── lib/                    # الاتصال بالـ API، المصادقة، أدوات التنسيق
├── schema.sql                  # مخطط قاعدة البيانات
├── seed.sql                    # البيانات الأولية (حساب المدير + الإعدادات)
├── wrangler.toml               # إعداد Cloudflare
└── google-apps-script.js       # سكربت النسخ الاحتياطي
```
